# The architecture can be divided into several layers:

- Model Adapters: These classes receive prompts and parse the model inputs and outputs.
- Action Adapters: This layer is responsible for executing the actions generated by the model adapters. It takes the actions and converts them into a format that can be executed by the robot's control system.
- Action Executors: These classes execute the actions on the robot.
- Model Clients: These classes handle communication with the AI models.
- RFM Action Server: This is the entry point for the user. It receives the prompt, calls the model adapter and action adapter. It also subscribe to the cameras and the joints states.

The following diagram shows how the different components interact with each other:
![architecture](../../../docs/images/tng_rfm_control.svg)


1. The `RfmActionServer` is called with a prompt by the user / rfm client.
2. The `RfmActionServer` calls a `ModelPort` with the prompt.
3. The `ModelPort` parses the prompt, images and the current robot state and sends it to its corresponding `ModelClient`.
4. The model client calls the AI model and passes the output back to the model adapter.
5. The `ModelPort` parses the model output (`ModelOutputMapper`) and generates intermediate actions.
6. The `ModelPort` passes the actions back to the `RfmActionServer`.
7. The `RfmActionServer` calls the `ActionPort` with the actions.
8. The `ActionMapper` converts the actions into a format that can be executed by the `ActionExecutor`.
9. The `ActionPort` passes the executable actions to an `ActionExecutor`.
10. The `ActionExecutor` executes the actions on the robot.
11. The `RfmActionServer` repeates step 2. for 4 iterations
